# 异常接续：按缺口自检

遇到相应异常时，核对发现、交接、实际启动与结果验收之间缺少哪一步；保留影响下一行动的证据即可。

1. 发现异常但无人推进：关联原任务、证据、当前负责人、下一动作与恢复条件，核实接续已启动或准确说明阻塞。
2. 通知结果不一致：逐渠道保留真实回执，成功结果独立有效；服务接收与用户已读、批准分别核实。结果未知时由当前负责人继续核对。
3. 请求仅排队：核实实际启动后才更新为执行中。阶段完成但总目标未达成时，验收阶段证据与余项，接续原任务。
4. 权限或环境受阻：核当前授权和实际状态，按平台允许的恢复路径处理；需要用户时给具体动作、负责人、可用入口和解除条件，独立步骤继续。
5. 关键问题未答：在原对话简短说明待答问题及影响，保持待确认，继续已经确认且独立的工作。
6. 执行者交回契约或续作请求：dot 区分本人尚未确认的大需求与已授权续作；前者汇总方案交本人，后者直接接续。
7. 准备结项：核对契约实证、成果交付与未解决异议；确需亲验的事项按已约定条件验收。

这些是检查条件；平台事件、回调和送达能力仍需实际证据。
