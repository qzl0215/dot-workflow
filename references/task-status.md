# 低成本任务状态与时报

在派发需持续跟踪的任务、接收其变化或制作任务时报时读取。原 Linear 事项是默认底账；没有接入时沿项目已有记录，不建立另一份任务库。更晚且属于同一任务/轮次的用户决定、实际执行和产物证据可以纠正进展与验收判断；当前是否运行须实读独立 Codex 线程状态，单个运行圈、接口标签、更新时间或旧线程终态不能覆盖任务事实。

## 一次绑定，执行端维护

向已授权的专属线程派发时带 `/workflow` 和以下最小协议；具体值来自原记录和真实回执，不把示例占位符作为派发内容：

```yaml
workflow-track: linear/v1
issue: <已核原 Issue ID 或 URL>
coordinator_thread: <协调线程 ID>
executor_thread: <执行线程 ID>
state_writer: <当前唯一写者线程 ID>
```

宿主不唯一时附宿主标识；创建前没有执行线程 ID 就明确待回执绑定，创建成功后补齐，不猜 ID。只启用获本人授权范围的状态维护。执行者实读兼容版本 workflow 的 `references/linear-tracking.md`，普通 `/workflow` 不增加 Linear 调用。未安装兼容版或不具备现有工具时保留原写者并回报缺口，不冒称已接管、不新开权限。标记绑定原任务，在该线程直接续作时持续有效，不让本人重复填写。

有专属执行者时，由它直接更新原 Issue 当前摘要和必要的原生状态；dot 平时读取，不抄写第二份执行回执。写权转移先由旧写者确认停写且无未决请求，新写者读回最后版本并确认接手，之后只有新写者修改。线程结束或超时本身不是交接；不能确认旧写者停下时不抢写。其他线程给事实，写者按原记录收敛；多线程同交付仍只有一个当前状态写者。状态写权未接手不阻止已授权且无冲突的业务工作，变化交现写者同步；不要把维护协议变成新的执行审批门。

当前摘要只需：Issue/线程/写者映射、当前阶段与状态、下一动作与责任、等待原因/恢复条件、证据、最后有效变化 `progress_at` 和最近核验 `observed_at`。原位更新，保留长期目标和历史依据。真实步骤、产物、阻塞或责任变化才推进 `progress_at`；标题修改、格式化、同状态检查及更新时间刷新不能算新进展。未知时间保留未知。摘要中的 `running` 是保存时的观察，不能证明线程现在仍在运行；`phase`、业务证据和 `progress_at` 只说明进展。🔧进行中必须另核独立 Codex 线程当前状态，不能由原生 Issue 状态、更新时间、历史回复或产物推断。

## 发报时只补必要证据

### 紧凑摘要与固定生成

有字段选择能力时显式请求 `id,title,status,statusType,updatedAt,dueDate,url` 等本轮必要字段，省略默认长描述、人员和历史。任务轻量目录与线程近期目录独立读取时并行；同轮已知要核的详情也按依赖并行，不为了分批而多次让模型往返。用实际成功水位和少量重叠时间窗读取任务变化，按 ID/版本去重；失败或分页未齐不推进水位。变化事项需要摘要时在一次列表中附 `description`，正文截断不能冒充完整结果。未知字段能力沿宿主真实工具，不改用额外认证。

兼容 workflow 的唯一写者在原当前区块最前面维护 `<!-- task-report:v1 -->` 与 `<!-- /task-report -->` 包围的一行 JSON，整个首摘要不超过420字符，放在描述前460字符内。沿用原 Issue 的一份当前状态：`zone`（decision/followup/future/dot/recover/done）、`phase`、`next`、`owner`（本人=user）、已核 `thread`、`writer`、`progress_at`、`observed_at`、`running` 与 `paused`；宿主和关键证据可补 `host`/`evidence`。时间含时区，未知为null。文字太长缩短阶段和下一动作，不能截身份与时间；更多依据留该区块后部。原写者遇真实变化时更新，不全库迁移或刷进展。

现有宿主可运行 Python 时优先调用 [固定时报生成器](../scripts/task_report.py)，不用模型重新排列和改写无争议事项。输入对象包含：`now`（报告截点，含时区）、`issues`（原任务轻量完整清单，变化项可附首摘要）、`threads`（本轮读取的目录，含id/updatedAt/status）、`baseline`（上一轮输出）和 `coverage`。本轮开始读取状态时记录 `observation_started_at`；每个已核线程记录实际读取时刻 `observed_at`，须落在该开始时间至 `now` 之间。只有工具明确证明当前运行才将线程 `status` 规范为 `running`；排队、待启动分别保留 `queued`/`pending`/`starting`，停止保留 `idle`/`completed`/`failed`/`interrupted`。模糊的 active 或未加载标签不自行映射，状态不可核就留未知。省略开始时间仅接受与 `now` 同刻的状态观察，不从旧基线补当前状态。

coverage以 `issues_complete`/`threads_complete` 表示本轮范围分页完整性，并用 `label` 说明实际范围；已知不变的来源缺口可设 `unchanged_gap=true`，但新增缺口仍需核，不声称全桌面覆盖。基线行保存原Issue版本与已核摘要；同版本可复用进展事实，不能复用成当前运行状态，版本变化、截断或输入冲突即失效。缺摘要的旧任务可由本轮已核事实补入同格式基线，不伪造已写回原Issue；其他任务仍由自己的原写者维护。

输出的 `report` 是按话题分区、一事一行的五区业务表格，`checks`/`sources`/`baseline` 保留诊断码、身份、来源与原证据等追溯详情；脚本没有网络、写入、接续或通知副作用。输入的标题、`phase` 与 `next` 使用业务语言，不能靠脚本理解或改写哈希、测试数和任务代号；确需另取业务简称时可提供 `business_title`，原始标题仍留追溯。`routine_ready=true` 时沿原时报入口发送，不让模型再扩写长历史。否则AI只处理check涉及的模糊事实、冲突、过期、未映射或新覆盖缺口，取得可信事实后重生成；稳定已披露的覆盖缺口保留在报文，不每轮重复诊断。发送字数或本人注意力限制仍由原渠道执行，不靠裁剪丢任务冒充完整。

生成器保留旧首摘要格式；没有本轮明确的线程运行状态时，dot 区显示⏳等待当前状态回执，历史 `running=true` 或新产物均不放行。停止和排队分别显示，保留具体下一步，不擅自回写原状态。当前线程状态比摘要更新时可据其显示，并将摘要冲突交当前写者核对；暂停或本人等待不因界面活动自动改为执行。`thread_observations` 保留本轮状态来源与读取时间用于追溯，不作为下一轮运行证明。程序检查输入和观察窗口，状态来源是否准确由读取者负责，不把格式通过当成实际运行证明。

原Project中明确登记的独立任务也必须保留：输入另附 `tasks`，每项含稳定原任务定位 `id`、`title`、`source_kind=project_task`、真实原Project/任务URL `source_ref`、实际源版本 `updatedAt`（未知不造），以及同首摘要格式的已核 `row`。没有独立原任务ID时，可用已核原ProjectID与该任务已有定位构成派生键，并说明是读取定位，不能称新Issue；同一Project的其他独立交付不合并。row复用原任务/实际线程的有效回执，不能凭Project整体状态推某任务Done。输出报文、`sources`和基线保留原来源与真实线程；缺来源/映射明确check，不以常规完成掩盖遗漏。无可信row时保留任务待核，不把外部任务塞进另一Issue或创建重复任务库。

线程目录若只有ID，传 `id` 与 `metadata_available=false`，不填 `updatedAt`。首次出现元数据缺口仍check；确认是已知稳定缺口时可用coverage的 `unchanged_gap=true`，固定报文仍披露缺口并保留原回执时间，不能把当前运行时间当新观察。新任务、未知来源、未映射、变更、原生状态冲突与超时不受该选项豁免；无法发现更晚续作的可见性限制必须写清，不把 `routine_ready` 当所有宿主状态已核。

原Canceled/Done且已经核终结、没有更晚业务活动的任务，输入可附 `terminal_verified=true` 与真实 `terminal_evidence`，必要时附原已核 `terminal_observed_at`。该标记是读取者的证据事实，不提供行动或写权限；不能仅凭原生状态补标，也不为终结项伪造writer/thread。程序保留在 `closed` 与基线，退出当前待办，原版本变化即重新核；`new_activity=true`、更晚已绑定线程活动或当前摘要仍有未完动作都会阻止过滤。已核取消不自动重启，阶段完成不补为已核总目标结束。

已有完整已核当前摘要的 `zone=done`，且原生终结状态一致时，可直接复用同源版本的结束事实。基线保存原观察时间与真实绑定，后续新活动和当前目录丢失仍核。输出 `task_checks` 是任务例外，`scope_checks` 是目录/覆盖缺口；未知目录不能直接变成本人业务待办或唤醒请求，也不能为了快速通过而移除。

目录中只有既有有效基线已核为历史非业务的项，可附 `scope=historical_nonbusiness` 和真实 `scope_evidence`。输出 `excluded_threads` 及范围说明保留分类依据；没有依据、新未知或 `new_activity=true` 仍待核，当前原任务绑定该线程时按范围冲突核，不盲排除。此分类受最新用户续作/来源变化影响，不是永久黑名单；目录只有ID时仍披露无法发现更晚活动的可见性限制。没有专属线程但已核等待事实和原任务URL的事项，使用原任务入口，不能为填链接制造线程；声称实际运行时仍需真实执行入口。

任务已Done但有更晚线程活动仍进入检查；严格超过一小时才触发超时，普通更新时间不能刷新进展；暂停保持未来待办，无日期不催。程序保留基线中本轮不可见的原任务并标缺口，未知不自动判完成。它不决定用户授权、写权转移、经营优先级或健康线程是否该重启；这些只在异常分支按既有证据判断。原自动化接入后核实际生成和发送回执，不把新增脚本或改prompt当生效。

首次或现有覆盖记录丢失时，建立任务与线程的轻量关联基线：读取范围内原任务摘要、可见线程目录及分页信息，只对未映射/矛盾项读取必要原文。之后复用协调线程已有映射、有效摘要和读取游标；这是可重建的工作上下文，不是新数据库或第二真源。

每轮完整保留范围内原任务清单及用户已指出但尚未映射的任务。先取任务状态/更新时间等轻量变化和可见线程近期元数据；工具无可靠增量时分页读取轻量目录，不逐项读所有线程历史。`updatedAt` 只筛选可能变化，不证明有效进展；分页截断、宿主不可见或游标不连续必须说明覆盖缺口，必要时重建受影响范围的轻量基线。

只展开两类事项：

1. In Progress 且距最后有效变化严格超过一小时，或有效变化时间未知；线程与记录冲突也直接核对，不等满一小时。
2. 近期有新轮次/用户续作/交付/暂停等变化的已绑定线程，以及新发现未映射的相关线程。不受原 Issue 为 Todo、等待或 Done 限制；明确暂停仍以本人后续决定为准，不能由界面活动自动恢复。

优先消费同版本已核回执；缺证才读对应最新轮次/产物，不回读整条长历史。可信实证更晚但 Linear 滞后时，本轮报告可以按已核事实呈现并标明待同步，由当前写者修正；dot 未接手前不并发改写。线程当前不可达仍保留任务和最后证据时间，不把不可见当不存在或停止。若执行宿主可读、协调接口因格式或能力不支持而不可读，沿原关联保留已核线程 ID、证据读取宿主/来源和时点，明确协调端可读性缺口；复用有效回执，不将错误或空返回删除成无任务，不反复重试同一不支持入口，也不擅自扩成平台接入改造。

## 一小时兜底的动作

复用已授权时报的既有调度，不新增常驻进程、轮询自动化或每小时假心跳。阈值用于发报前核验，不承诺超过一小时立即触发；夜间或停报窗口照原约定。停止后的即时通知与接续沿既有事件/回执通道单独验收，不能用时报轮询冒充即时保障。

- 已有真实运行：核当前步骤/产物/资源等待。缺进展证据时向原执行者请求状态；先用宿主只读或不新开 turn 的运行中通信能力，不发送会排队成新执行的普通“继续”，不重复启动、重放或打断健康长步骤。宿主无此能力则记证据缺口。
- 线程已终态或当前未运行：核总目标与下一责任，明确自行继续执行、交付验收、等待具体条件或暂停；原授权内下一步明确且就绪就沿原入口接续。启动请求先报⏳等待回执，当前状态核实独立线程正在运行后才报🔧进行中；已有待处理请求先核结果，不重复派发，不停着没有下一步。
- 本人暂停/取消、待本人决策或操作：校正状态及具体恢复条件，不盲唤。本人明确暂停且无当前动作时归入📅未来待办，注明暂停、无到期催办；不能放入🚨待dot重新跟进冒充异常。明确未来时点未到不催，阶段交付不直接 Done。
- 读取/写入失败、未映射或写权冲突：保留原任务与缺口，归 dot 负责接续；用一个最小诊断区分原因，不重复同样失败，也不要求本人重述可查事实。

## 五区与验收

按下一责任保留五区：🔵本人取舍、🟠本人操作或验收、📅未来或暂停、dot 推进与待核、🚨dot 恢复与核查；前两区只放本人具体动作。dot 区逐项用🔧标已核独立线程当前运行，用⏳标当前状态待核、排队或等待条件；停止的事项必须有具体下一步，不能沿旧进展报运行。正常排队/资源等待不因等待本身归异常区。待核是区内证据状态，不建第六区。

按 [汇报](../SKILL.md#汇报)用具体话题开头、业务表格分区，一事一行，呈现结果或卡点、下一步与必要的本人取舍；已核入口和影响判断的证据时间随项保留。任务代号、技术校验与诊断码留原任务及结构化追溯详情，不能让用户靠代码判断下一步。同任务去重保留所有相关入口，独立交付不合并。报告写明核对时点、覆盖范围及缺口，用户纠正进入原 Issue，不另建清单。

用同组真实时间线回放任务遗漏、旧终态、新轮次、本人暂停、超一小时仍在跑和写权冲突；阶段产物可用不等于整体完成。分别记录漏项/误报、入口映射、证据新鲜度、首报耗时、读取/写入/启动工具次数和本人纠偏次数。无数字基线不报改善率；静态规则检查、模型判断探针、真实状态回写与真实时报送达分别报告，不互相替代。
