# 低成本任务状态与时报

在派发需持续跟踪的任务、接收其变化或制作任务时报时读取。原 Linear 事项是默认底账；没有接入时沿项目已有记录，不建立另一份任务库。更晚且属于同一任务/轮次的用户决定、实际执行和产物证据可以纠正状态；单个运行圈、接口标签或旧线程终态不能覆盖任务事实。

## 一次绑定，执行端维护

向已授权的专属线程派发时带 `/workflow` 和以下最小协议；具体值来自原记录和真实回执，不把示例占位符作为派发内容：

```yaml
workflow-track: linear/v1
issue: <已核原 Issue ID 或 URL>
coordinator_thread: <协调线程 ID>
executor_thread: <执行线程 ID>
state_writer: <当前唯一写者线程 ID>
```

宿主不唯一时附宿主标识；创建前没有执行线程 ID 就明确待回执绑定，创建成功后补齐，不猜 ID。只启用获本人授权范围的状态维护。执行者实读兼容版本 workflow 的 `references/linear-tracking.md`，普通 `/workflow` 不增加 Linear 调用。未安装兼容版或不具备现有工具时保留原写者并回报缺口，不冒称已接管、不新开权限。标记绑定原任务，在该线程直接续作时持续有效，不让本人重复填写。

有专属执行者时，由它直接更新原 Issue 当前摘要和必要的原生状态；dot 平时读取，不抄写第二份执行回执。写权转移先由旧写者确认停写且无未决请求，新写者读回最后版本并确认接手，之后只有新写者修改。线程结束或超时本身不是交接；不能确认旧写者停下时不抢写。其他线程给事实，写者按原记录收敛；多线程同交付仍只有一个当前状态写者。状态写权未接手不阻止已授权且无冲突的业务工作，变化交现写者同步；不要把维护协议变成新的执行审批门。

当前摘要只需：Issue/线程/写者映射、当前阶段与状态、下一动作与责任、等待原因/恢复条件、证据、最后有效变化 `progress_at` 和最近核验 `observed_at`。原位更新，保留长期目标和历史依据。真实步骤、产物、阻塞或责任变化才推进 `progress_at`；标题修改、格式化、同状态检查及更新时间刷新不能算新进展。未知时间保留未知。

## 发报时只补必要证据

首次或现有覆盖记录丢失时，建立任务与线程的轻量关联基线：读取范围内原任务摘要、可见线程目录及分页信息，只对未映射/矛盾项读取必要原文。之后复用协调线程已有映射、有效摘要和读取游标；这是可重建的工作上下文，不是新数据库或第二真源。

每轮完整保留范围内原任务清单及用户已指出但尚未映射的任务。先取任务状态/更新时间等轻量变化和可见线程近期元数据；工具无可靠增量时分页读取轻量目录，不逐项读所有线程历史。`updatedAt` 只筛选可能变化，不证明有效进展；分页截断、宿主不可见或游标不连续必须说明覆盖缺口，必要时重建受影响范围的轻量基线。

只展开两类事项：

1. In Progress 且距最后有效变化严格超过一小时，或有效变化时间未知；线程与记录冲突也直接核对，不等满一小时。
2. 近期有新轮次/用户续作/交付/暂停等变化的已绑定线程，以及新发现未映射的相关线程。不受原 Issue 为 Todo、等待或 Done 限制；明确暂停仍以本人后续决定为准，不能由界面活动自动恢复。

优先消费同版本已核回执；缺证才读对应最新轮次/产物，不回读整条长历史。可信实证更晚但 Linear 滞后时，本轮报告可以按已核事实呈现并标明待同步，由当前写者修正；dot 未接手前不并发改写。线程当前不可达仍保留任务和最后证据时间，不把不可见当不存在或停止。若执行宿主可读、协调接口因格式或能力不支持而不可读，沿原关联保留已核线程 ID、证据读取宿主/来源和时点，明确协调端可读性缺口；复用有效回执，不将错误或空返回删除成无任务，不反复重试同一不支持入口，也不擅自扩成平台接入改造。

## 一小时兜底的动作

复用已授权时报的既有调度，不新增常驻进程、轮询自动化或每小时假心跳。阈值用于发报前核验，不承诺超过一小时立即触发；夜间或停报窗口照原约定。停止后的即时通知与接续沿既有事件/回执通道单独验收，不能用时报轮询冒充即时保障。

- 已有真实运行：核当前步骤/产物/资源等待。缺进展证据时向原执行者请求状态；先用宿主只读或不新开 turn 的运行中通信能力，不发送会排队成新执行的普通“继续”，不重复启动、重放或打断健康长步骤。宿主无此能力则记证据缺口。
- 线程已终态：核总目标与下一责任；原授权内下一步明确且就绪才沿原入口接续，取得启动回执后报进行中；已有待处理请求先核结果，不重复派发。
- 本人暂停/取消、待本人决策或操作：校正状态及具体恢复条件，不盲唤。本人明确暂停且无当前动作时归入📅未来待办，注明暂停、无到期催办；不能放入🚨待dot重新跟进冒充异常。明确未来时点未到不催，阶段交付不直接 Done。
- 读取/写入失败、未映射或写权冲突：保留原任务与缺口，归 dot 负责接续；用一个最小诊断区分原因，不重复同样失败，也不要求本人重述可查事实。

## 五区与验收

按下一责任归入 🔵待你决策、🟠待你跟进、📅未来待办、🔧dot进行中、🚨待dot重新跟进；前两区只放本人具体动作。正常排队/资源等待注明未实际执行，不计入真实执行数；不因等待本身归异常区。待核是区内证据状态，不建第六区。每项分行给当前阶段、下一动作/责任、已核执行入口和影响判断的证据时间；同任务去重保留所有相关入口，独立交付不合并。报告写明核对时点、覆盖范围及缺口，用户纠正进入原 Issue，不另建清单。

用同组真实时间线回放任务遗漏、旧终态、新轮次、本人暂停、超一小时仍在跑和写权冲突；阶段产物可用不等于整体完成。分别记录漏项/误报、入口映射、证据新鲜度、首报耗时、读取/写入/启动工具次数和本人纠偏次数。无数字基线不报改善率；静态规则检查、模型判断探针、真实状态回写与真实时报送达分别报告，不互相替代。
