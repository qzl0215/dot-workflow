# dot-workflow

把目标问清、选择简洁方案，并持续推进到有证据的结果。面向研究、文档、工程和持续跟进的中文工作流技能。

[SKILL.md](SKILL.md) 是规则入口：小请求直接完成；大需求收敛需求契约与方案，按用户明确授权执行，已有授权直接复用；调查、方法选择、实施和验证由 AI 自主推进，确需用户介入才交最小事项。结果按实证验收，最后做有价值的复盘。保留图标短报，工具和任务系统按实际接入能力使用。

## 使用

让支持技能的助手使用 `$dot-workflow`，或让它读取本项目 `SKILL.md`。宿主是否支持自动匹配，以实际加载结果为准。

线程选择兼顾连续性和上下文成本：上下文不长且实际相关度高于 70% 时优先复用；这是启发式，不是精确评分。否则新开线程，交代最小必要背景。

技能本身不建立工具连接、后台守护或通知通道。Linear 可选；没有接入时沿用项目已有任务记录。复杂任务调用执行助手仍以用户授权和宿主能力为准。

持续跟踪任务以原 Linear 事项为底账，可信派发标记让兼容 workflow 按需维护；专属执行者直接更新原记录，dot 读取汇总。时报复用已核映射，仅对过期、变化或冲突项核验，覆盖用户在等待线程中直接续作。规则与能力边界见 [任务状态与时报](references/task-status.md)，不新增常驻服务。

## 安装与更新

从 [Releases](https://github.com/qzl0215/dot-workflow/releases) 下载指定正式版本的 `dot-workflow.zip` 与 `SHA256SUMS`，核对下载包 SHA-256，再核对包内 `manifest.json` 的版本、完整 commit 和逐文件 SHA-256。仅安装经核对的 `dot-workflow/` 内容。

首次安装按宿主的技能导入入口进行；更新由原技能唯一维护者在同一技能身份下替换运行文件，保留已有安装身份。安装目录由宿主配置确定，不能凭示例猜测。先在暂存位置核验，再激活；旧版恢复材料留在宿主不会发现的备份位置。

更新后由安装者回读技能名称与正文，以分发包 manifest 核对版本和文件哈希、引用及图标，并以一个最小任务确认实际加载；已有会话可能保留旧上下文，按宿主机制重新加载。交接同一份安装与加载证据，其他角色仅补验缺失、冲突或变化的部分。扩大模拟须能改变验收结论。发布、安装保存和加载生效分别报告，只有正式安装回读与实际加载成立，才能声明更新生效。

仓库是公开内容的单一源码真源，安装结果不维护另一套规则。发布资产包含技能正文与参考、时报生成器、图标、项目许可和来源说明，以及生成的校验清单。

### 常规时报的快速路径

现有执行宿主有 Python 3.9+ 时，使用 `python3 -B scripts/task_report.py snapshot.json`；也可由标准输入传 JSON。脚本不联网、不维护任务、不启动线程、不发送通知，只输出五区文本、异常清单及可重建基线。现有时报入口负责取数和沿原渠道发送，无需新服务或认证；无 Python 的宿主沿同一规则汇总并说明程序路径未接入。

输入与摘要格式见 [任务状态与时报](references/task-status.md)。`routine_ready=true` 时直接消费固定报文；否则只处理 `checks` 指向的缺证/冲突，取得新的可信事实后再生成。保留报告核对时间和覆盖范围，调用成功不代表送达。

## 维护

维护需要 Python 3.9+ 和 Git，检查及打包只使用 Python 标准库；可选时报生成器也仅用标准库，其余技能运行不依赖 Python。

```sh
python3 -B scripts/check.py
python3 -B -m unittest discover -s tests -p 'test_*.py'
```

每次改动使用独立分支与 worktree，审阅差异后直接 merge 到最新 main，不设 PR 门槛。最终合并树验证、发布、下载回验和安装交接见 [CONTRIBUTING.md](CONTRIBUTING.md)。行为验收场景与证据边界见 [evals/cases.md](evals/cases.md)。
